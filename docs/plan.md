# 데이터 보강 계획 (24시간·심야 영업 여부 · 반려동물 여부)

최초 작성: 2026-10-31 / 결정 사항 반영: 2026-10-31

## 1. 배경과 목표

- 프로젝트의 출발점은 **밤늦게 공부할 수 있는 곳 찾기**이고, 그래서 카페가 중요하다.
- 현재 `data/places.json`에는 강남역 반경 1km의 음식점·카페 **2,513개**가 있다. (카카오 로컬 API로 수집)
- 각 항목의 `is_24h`(24시간 여부)와 `pet_friendly`(반려동물 여부)는 아직 모두 `"확인 필요"`다.
- 이 문서는 두 값과 마감 시각을 채우는 계획이다.
  - 24시간·마감 시각: **Google Places API**
  - 반려동물 여부: **네이버 검색 결과를 모아 두고 Claude Code가 직접 읽고 판별** (별도 API 결제 없음)
  - 이름에 "24시"가 들어간 가게 거르기: **보조 수단**으로만 사용

## 3. 24시간·마감 시각: Google Places API (New)

### 3-1. 조회 범위: 900개

카카오 API는 영업시간을 주지 않으므로, 2,513개 전체가 아니라 후보 900개만 구글에 조회한다. 대상 목록은 `python scripts/select_scope.py`로 만들고 `data/scope.json`에 저장한다.

| 구분 | 기준 | 개수 |
|---|---|---|
| 이름 기준(보조) | 이름에 "24시" 또는 "24h" 포함. 항상 포함 | 1 |
| 심야 업종 | 카테고리에 국밥·해장·설렁탕·순대·곰탕·감자탕·햄버거·패스트푸드·분식·김밥·치킨 중 하나가 포함 | 293 |
| 술집 | 카테고리에 "술집" 포함 | 273 |
| 카페 | 위에 해당하지 않는 카페를 강남역에서 가까운 순으로 채움 (가장 먼 곳이 약 695m) | 333 |
| **합계** | | **900** |

- 카페를 가까운 순으로 자르는 이유: 공부할 곳을 찾는 용도라 접근성이 중요하고, 영업시간 조회 무료 한도(월 1,000건)를 넘지 않게 맞추기 위해서다.
- 이름에 "24시"가 들어간 가게는 1개뿐이다. 범위 선정과 구글 결과 교차 확인에만 쓰는 보조 수단이다.
- `TARGET`(기본 900)은 `scripts/select_scope.py` 상단에서 바꿀 수 있다.

### 3-2. 호출 순서

1. **Text Search (Pro 등급)**: 가게 이름과 좌표(`locationBias`)로 검색해 `place_id`를 찾는다.
   - 응답 필드는 `id, displayName, location, businessStatus`만 요청한다. (모두 Pro 등급 이하)
   - 이름과 좌표가 카카오 데이터와 충분히 가까울 때만 같은 가게로 인정한다.
   - 폐업이면 영업시간을 조회하지 않는다.
2. **Place Details (Enterprise 등급)**: `regularOpeningHours`만 요청한다.

### 3-3. 비용과 안전장치 (2026-10-31 공식 문서 기준)

| 호출 | 등급 | 월 무료 한도 | 한도 초과 시 1,000건당 |
|---|---|---|---|
| Text Search (Pro 필드) | Pro | 5,000 | $32 |
| Place Details (`regularOpeningHours`) | Enterprise | 1,000 | $20 |

- 900개 기준: 찾기 900건 + 영업시간 최대 900건 → 둘 다 무료 한도 안이라 **$0**.
- 참고: 2,513개 전체를 조회하면 영업시간 조회가 약 **$30**이다. Text Search로 영업시간까지 한 번에 받으면 $35/1,000이라 더 비싸다.
- 가격과 한도는 바뀔 수 있으니 키를 받은 뒤 Google Cloud 콘솔의 가격 페이지에서 한 번 더 확인한다.
- Google Cloud 콘솔에서 Places API의 **일일 요청 한도(쿼터)** 를 걸고, 예산 알림을 $1로 설정한다.
- 조회 결과를 파일에 저장해 두고, 다시 실행해도 이미 조회한 가게는 건너뛴다. (중복 과금 방지)
- 처음에는 20개만 시험 실행해서 결과와 청구 내역을 확인한 뒤 전체를 돌린다.

### 3-4. 판별 방식과 저장 값

응답의 `regularOpeningHours.periods`를 기준으로 요일별 영업 시각을 계산한다.

- **`is_24h`**
  - `"예"`: 7일 모두 0시 0분에 열고, 닫는 시각이 없거나 하루 종일 이어짐
  - `"아니오"`: 영업시간이 있고 위 조건에 해당하지 않음
  - `"확인 필요"`: 영업시간 정보가 없거나 가게 매칭에 실패함
- **`closes_at`**: 요일별 마감 시각. 예: `{"mon": "02:00", "tue": "02:00", ..., "sun": "24h"}`. 24시간인 날은 `"24h"`, 쉬는 날은 `null`, 정보가 없으면 필드 전체를 `null`로 둔다. 자정을 넘기는 영업은 다음 날 시각으로 적는다.
- **`late_night`**: 24시간이거나, 마감 시각이 **자정(00:00) 이후**인 요일이 하나라도 있으면 `"예"`, 그 외 `"아니오"`, 영업시간 정보가 없으면 `"확인 필요"`. (2026-10-31 결정: 처음 제안한 새벽 2시 기준에서 자정으로 변경)
  - 정확히 자정에 마감하는 곳은 자정 "이후"가 아니므로 심야에 넣지 않는다. 자정을 넘겨 00:01 이후에 마감하는 곳부터 심야다.
  - 기준 시각은 스크립트 상단 상수로 두어 나중에 바꿀 수 있게 한다.
  - 기준이 넓어져서 심야로 분류되는 가게가 늘어나고, 그만큼 반려동물 판별 대상(4-1)도 늘어난다. 구글 조회 결과가 나오면 대상 수를 확인하고, 너무 많으면 여러 세션에 나눠 진행한다.
  - 반려동물 판별 대상(4-1)을 정하는 기준이기도 하다.
- 이름에 "24시"가 있는데 구글이 24시간이 아니라고 하면 값을 바꾸지 않고 확인 대상 목록에 따로 모은다.

### 3-5. 지도에 영업시간을 보여줄 때의 표시 방안 (2026-11-02 추가)

구글 영업시간은 출처에 따라 실제와 다를 수 있다. 시험에서 같은 가게(빽다방 강남역지하도점)의 평일 마감이 카카오 20:00, 구글 22:00으로 달랐다. 그래서 말풍선에 영업시간을 표시할 때는 다음을 지킨다.

- 영업시간·마감 시각 옆에 **"구글 기준, 실제와 다를 수 있음"** 문구를 붙인다.
- 24시간·심야 값도 같은 문구를 달고, 반려동물 값은 "AI 추정"(4-3)으로 따로 표시한다.
- 매칭이 `확정(이름 차이 확인 필요)`이었다가 사람이 승인한 가게는 데이터에 승인 여부를 남기되, 화면에서는 구분하지 않는다.
- 영업시간 정보가 없거나 매칭이 되지 않은 가게는 "영업시간 정보 없음"으로 표시하고 심야 필터에서 제외한다.
- 출처 두 곳이 서로 다른 값을 줬다는 사실은 화면이 아니라 `docs/devlog.md`에 사례로 남겨 둔다.

## 4. 반려동물 여부: 네이버 검색 결과 + Claude Code 직접 판별

별도 AI API 키를 결제하지 않는다. 스크립트는 네이버 검색 결과를 모으는 일만 하고, 읽고 판단하는 일은 Claude Code 세션에서 직접 한다.

### 4-1. 판별 대상

- 구글 조회 결과에서 `is_24h == "예"` 이거나 `late_night == "예"`인 가게만 대상으로 한다.
- 대상 수는 구글 조회가 끝나야 알 수 있다. 900개 중 일부일 것이다.
- 영업시간을 알 수 없는(`"확인 필요"`) 가게는 대상에서 제외하고, 확장 과제(9)로 넘긴다.

### 4-2. 흐름

1. **모으기** (`scripts/collect_naver.py`, 네이버 키 필요): 대상 가게마다 네이버 블로그 검색(필요하면 카페글 검색)으로 `"{가게명} 강남 반려견 동반"` 등을 검색한다. 제목·요약문·링크 상위 약 10개를 `data/raw/naver_snippets.json`에 저장한다. (`data/raw/`는 `.gitignore`에 넣어 깃에 올리지 않는다.)
2. **판별** (Claude Code 세션): 사용자가 "반려동물 판별 시작"이라고 하면, Claude Code가 모은 파일을 약 20개 가게씩 끊어서 읽고 가게마다 `가능` / `불가` / `확인 필요`와 근거 문장을 정해 `data/pet_judgments.json`에 저장한다.
3. **반영** (`scripts/merge_pet_judgments.py`): 판별 결과를 `data/places.json`의 `pet_friendly`, `pet_evidence`에 합친다.

판별 규칙:
- 최근 글과 가게 본인·방문자의 직접 언급을 우선한다. 광고성·오래된 글, 다른 가게 이야기는 근거로 쓰지 않는다.
- 근거가 약하거나 글이 거의 없으면 `"확인 필요"`로 둔다. 추측으로 `"가능"`을 채우지 않는다.
- 근거 문장과 출처 링크를 항상 함께 저장해서 나중에 사람이 검증할 수 있게 한다.

### 4-3. 비용과 한계

- **추가 결제 없음**: Anthropic API 키가 필요 없다. 네이버 검색 API는 무료이고 하루 호출 한도가 있다. (애플리케이션당 25,000회로 알고 있으나 키를 받을 때 개발자센터에서 확인한다.)
- 대신 Claude Code 사용량이 든다. 가게당 요약문 약 10개(대략 3,000~4,000토큰)를 읽으므로, 대상이 많으면 여러 세션에 나눠서 진행한다. 판별 결과는 파일에 저장하므로 중간에 끊겨도 이어갈 수 있다.
- 사람이 대화로 맡겨야 시작되는 수작업 단계라 자동 반복 실행은 안 된다. 가게 데이터를 갱신할 때마다 같은 절차를 다시 해야 한다.
- 같은 글을 다시 읽으면 판단이 조금 달라질 수 있어서, 결과는 **"AI 추정"** 이다. 지도 말풍선에도 그렇게 표시한다.

## 7. 진행 순서

1. [완료] 카카오 지도 연결, 강남역 반경 1km 가게 2,513개 수집
2. [완료] 조회 범위 900개 선정 스크립트
3. [대기] Google Cloud 키 발급 + 쿼터·예산 알림 설정
4. [대기] 구글 조회: 20개 시험 → 900개 전체 → 영업시간 값 반영
5. [대기] 네이버 개발자센터 키 발급
6. [대기] 판별 대상(24시간·심야 가게) 확정 → 네이버 검색 결과 수집
7. [대기] Claude Code가 검색 결과를 읽고 반려동물 판별 → 결과 합치기
8. [대기] 지도 화면에 24시간·심야·반려동물 필터 추가

## 8. 키 관리

- 구글·네이버 키는 `.env`에만 저장한다. (`.env`는 `.gitignore`에 등록되어 있어 깃에 올라가지 않는다.)
- 키를 코드나 문서에 직접 적지 않는다.

## 9. 확장 과제 (마감 이후)

위 단계가 끝난 뒤, 여유가 있을 때 진행한다.

- **나머지 약 1,600개 영업시간 조회**: 한식·일식·양식·중식·나머지 카페 등 이번 900개에 들지 않은 가게. 구글 무료 한도가 매달 새로 채워지므로 한 달에 약 900개씩 나눠서 조회하면 추가 비용 없이 2개월 안에 끝낼 수 있다. 전체를 한 번에 조회하면 약 $30이다.
- **반려동물 판별 확대**: 새로 확인된 24시간·심야 가게에 같은 절차를 적용한다.
- **데이터 갱신**: 가게가 문을 닫거나 영업시간이 바뀌므로 주기적으로 다시 수집한다.
- **범위 확대**: 강남역 반경 1km 밖(예: 역삼·논현·신논현 일대).
