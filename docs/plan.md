# 데이터 보강 계획 (24시간·심야 영업 여부 · 반려동물 여부)

> **2026-11-03 방향 전환**: 카카오·구글 모두 API 결과를 미리 모아 저장하는 것을 허용하지 않는다고 확인했다. 그래서 아래 1~9장(가게 데이터를 모아 저장하고 `places.json`에 채우는 구조)은 **폐기된 계획**이다. 기록으로만 남긴다. 새 구조는 **10장**을 본다. 이 방향 전환의 경위는 `docs/devlog.md` #11에 있다.

## 1. 배경과 목표

- 프로젝트의 출발점은 **밤늦게 공부할 수 있는 곳 찾기**이고, 그래서 카페가 중요하다.
- 현재 `data/places.json`에는 강남역 반경 1km의 음식점·카페 **2,513개**가 있다. (카카오 로컬 API로 수집)
- 각 항목의 `is_24h`(24시간 여부)와 `pet_friendly`(반려동물 여부)는 아직 모두 `"확인 필요"`다.
- 이 문서는 두 값과 마감 시각을 채우는 계획이다.
  - 24시간·마감 시각: **Google Places API**
  - 반려동물 여부: **네이버 검색 결과를 모아 두고 Claude Code가 직접 읽고 판별** (별도 API 결제 없음)
  - 이름에 "24시"가 들어간 가게 거르기: **보조 수단**으로만 사용

## 3. 24시간·마감 시각: Google Places API (New)

### 3-1. 조회 범위: 900개

카카오 API는 영업시간을 주지 않으므로, 2,513개 전체가 아니라 후보 900개만 구글에 조회한다. 대상 목록은 `python scripts/select_scope.py`로 만들고 `data/scope.json`에 저장한다.

| 구분 | 기준 | 개수 |
|---|---|---|
| 이름 기준(보조) | 이름에 "24시" 또는 "24h" 포함. 항상 포함 | 1 |
| 심야 업종 | 카테고리에 국밥·해장·설렁탕·순대·곰탕·감자탕·햄버거·패스트푸드·분식·김밥·치킨 중 하나가 포함 | 293 |
| 술집 | 카테고리에 "술집" 포함 | 273 |
| 카페 | 위에 해당하지 않는 카페를 강남역에서 가까운 순으로 채움 (가장 먼 곳이 약 695m) | 333 |
| **합계** | | **900** |

- 카페를 가까운 순으로 자르는 이유: 공부할 곳을 찾는 용도라 접근성이 중요하고, 영업시간 조회 무료 한도(월 1,000건)를 넘지 않게 맞추기 위해서다.
- 이름에 "24시"가 들어간 가게는 1개뿐이다. 범위 선정과 구글 결과 교차 확인에만 쓰는 보조 수단이다.
- `TARGET`(기본 900)은 `scripts/select_scope.py` 상단에서 바꿀 수 있다.

### 3-2. 호출 순서

1. **Text Search (Pro 등급)**: 가게 이름과 좌표(`locationBias`)로 검색해 `place_id`를 찾는다.
   - 응답 필드는 `id, displayName, location, businessStatus`만 요청한다. (모두 Pro 등급 이하)
   - 이름과 좌표가 카카오 데이터와 충분히 가까울 때만 같은 가게로 인정한다.
   - 폐업이면 영업시간을 조회하지 않는다.
2. **Place Details (Enterprise 등급)**: `regularOpeningHours`만 요청한다.

### 3-3. 비용과 안전장치 (2026-10-31 공식 문서 기준)

| 호출 | 등급 | 월 무료 한도 | 한도 초과 시 1,000건당 |
|---|---|---|---|
| Text Search (Pro 필드) | Pro | 5,000 | $32 |
| Place Details (`regularOpeningHours`) | Enterprise | 1,000 | $20 |

- 900개 기준: 찾기 900건 + 영업시간 최대 900건 → 둘 다 무료 한도 안이라 **$0**.
- 참고: 2,513개 전체를 조회하면 영업시간 조회가 약 **$30**이다. Text Search로 영업시간까지 한 번에 받으면 $35/1,000이라 더 비싸다.
- 가격과 한도는 바뀔 수 있으니 키를 받은 뒤 Google Cloud 콘솔의 가격 페이지에서 한 번 더 확인한다.
- Google Cloud 콘솔에서 Places API의 **일일 요청 한도(쿼터)** 를 걸고, 예산 알림을 $1로 설정한다.
- 조회 결과를 파일에 저장해 두고, 다시 실행해도 이미 조회한 가게는 건너뛴다. (중복 과금 방지)
- 처음에는 20개만 시험 실행해서 결과와 청구 내역을 확인한 뒤 전체를 돌린다.

### 3-4. 판별 방식과 저장 값

응답의 `regularOpeningHours.periods`를 기준으로 요일별 영업 시각을 계산한다.

- **`is_24h`**
  - `"예"`: 7일 모두 0시 0분에 열고, 닫는 시각이 없거나 하루 종일 이어짐
  - `"아니오"`: 영업시간이 있고 위 조건에 해당하지 않음
  - `"확인 필요"`: 영업시간 정보가 없거나 가게 매칭에 실패함
- **`closes_at`**: 요일별 마감 시각. 예: `{"mon": "02:00", "tue": "02:00", ..., "sun": "24h"}`. 24시간인 날은 `"24h"`, 쉬는 날은 `null`, 정보가 없으면 필드 전체를 `null`로 둔다. 자정을 넘기는 영업은 다음 날 시각으로 적는다.
- **`late_night`**: 24시간이거나, 마감 시각이 **자정(00:00) 이후**인 요일이 하나라도 있으면 `"예"`, 그 외 `"아니오"`, 영업시간 정보가 없으면 `"확인 필요"`. (2026-10-31 결정: 처음 제안한 새벽 2시 기준에서 자정으로 변경)
  - 정확히 자정에 마감하는 곳은 자정 "이후"가 아니므로 심야에 넣지 않는다. 자정을 넘겨 00:01 이후에 마감하는 곳부터 심야다.
  - 기준 시각은 스크립트 상단 상수로 두어 나중에 바꿀 수 있게 한다.
  - 기준이 넓어져서 심야로 분류되는 가게가 늘어나고, 그만큼 반려동물 판별 대상(4-1)도 늘어난다. 구글 조회 결과가 나오면 대상 수를 확인하고, 너무 많으면 여러 세션에 나눠 진행한다.
  - 반려동물 판별 대상(4-1)을 정하는 기준이기도 하다.
- 이름에 "24시"가 있는데 구글이 24시간이 아니라고 하면 값을 바꾸지 않고 확인 대상 목록에 따로 모은다.

### 3-5. 지도에 영업시간을 보여줄 때의 표시 방안 (2026-11-02 추가)

구글 영업시간은 출처에 따라 실제와 다를 수 있다. 시험에서 같은 가게(빽다방 강남역지하도점)의 평일 마감이 카카오 20:00, 구글 22:00으로 달랐다. 그래서 말풍선에 영업시간을 표시할 때는 다음을 지킨다.

- 영업시간·마감 시각 옆에 **"구글 기준, 실제와 다를 수 있음"** 문구를 붙인다.
- 24시간·심야 값도 같은 문구를 달고, 반려동물 값은 "AI 추정"(4-3)으로 따로 표시한다.
- 매칭이 `확정(이름 차이 확인 필요)`이었다가 사람이 승인한 가게는 데이터에 승인 여부를 남기되, 화면에서는 구분하지 않는다.
- 영업시간 정보가 없거나 매칭이 되지 않은 가게는 "영업시간 정보 없음"으로 표시하고 심야 필터에서 제외한다.
- 출처 두 곳이 서로 다른 값을 줬다는 사실은 화면이 아니라 `docs/devlog.md`에 사례로 남겨 둔다.

## 4. 반려동물 여부: 네이버 검색 결과 + Claude Code 직접 판별

별도 AI API 키를 결제하지 않는다. 스크립트는 네이버 검색 결과를 모으는 일만 하고, 읽고 판단하는 일은 Claude Code 세션에서 직접 한다.

### 4-1. 판별 대상

- 구글 조회 결과에서 `is_24h == "예"` 이거나 `late_night == "예"`인 가게만 대상으로 한다.
- 대상 수는 구글 조회가 끝나야 알 수 있다. 900개 중 일부일 것이다.
- 영업시간을 알 수 없는(`"확인 필요"`) 가게는 대상에서 제외하고, 확장 과제(9)로 넘긴다.

### 4-2. 흐름

1. **모으기** (`scripts/collect_naver.py`, 네이버 키 필요): 대상 가게마다 네이버 블로그 검색(필요하면 카페글 검색)으로 `"{가게명} 강남 반려견 동반"` 등을 검색한다. 제목·요약문·링크 상위 약 10개를 `data/raw/naver_snippets.json`에 저장한다. (`data/raw/`는 `.gitignore`에 넣어 깃에 올리지 않는다.)
2. **판별** (Claude Code 세션): 사용자가 "반려동물 판별 시작"이라고 하면, Claude Code가 모은 파일을 약 20개 가게씩 끊어서 읽고 가게마다 `가능` / `불가` / `확인 필요`와 근거 문장을 정해 `data/pet_judgments.json`에 저장한다.
3. **반영** (`scripts/merge_pet_judgments.py`): 판별 결과를 `data/places.json`의 `pet_friendly`, `pet_evidence`에 합친다.

판별 규칙:
- 최근 글과 가게 본인·방문자의 직접 언급을 우선한다. 광고성·오래된 글, 다른 가게 이야기는 근거로 쓰지 않는다.
- 근거가 약하거나 글이 거의 없으면 `"확인 필요"`로 둔다. 추측으로 `"가능"`을 채우지 않는다.
- 근거 문장과 출처 링크를 항상 함께 저장해서 나중에 사람이 검증할 수 있게 한다.

### 4-3. 비용과 한계

- **추가 결제 없음**: Anthropic API 키가 필요 없다. 네이버 검색 API는 무료이고 하루 호출 한도가 있다. (애플리케이션당 25,000회로 알고 있으나 키를 받을 때 개발자센터에서 확인한다.)
- 대신 Claude Code 사용량이 든다. 가게당 요약문 약 10개(대략 3,000~4,000토큰)를 읽으므로, 대상이 많으면 여러 세션에 나눠서 진행한다. 판별 결과는 파일에 저장하므로 중간에 끊겨도 이어갈 수 있다.
- 사람이 대화로 맡겨야 시작되는 수작업 단계라 자동 반복 실행은 안 된다. 가게 데이터를 갱신할 때마다 같은 절차를 다시 해야 한다.
- 같은 글을 다시 읽으면 판단이 조금 달라질 수 있어서, 결과는 **"AI 추정"** 이다. 지도 말풍선에도 그렇게 표시한다.

## 9. 확장 과제 (마감 이후)

위 단계가 끝난 뒤, 여유가 있을 때 진행한다.

- **나머지 약 1,600개 영업시간 조회**: 한식·일식·양식·중식·나머지 카페 등 이번 900개에 들지 않은 가게. 구글 무료 한도가 매달 새로 채워지므로 한 달에 약 900개씩 나눠서 조회하면 추가 비용 없이 2개월 안에 끝낼 수 있다. 전체를 한 번에 조회하면 약 $30이다.
- **반려동물 판별 확대**: 새로 확인된 24시간·심야 가게에 같은 절차를 적용한다.
- **데이터 갱신**: 가게가 문을 닫거나 영업시간이 바뀌므로 주기적으로 다시 수집한다.
- **범위 확대**: 강남역 반경 1km 밖(예: 역삼·논현·신논현 일대).

## 10. 새 구조: 실시간 조회 (2026-11-03, 초안 — 코드 작성 전 사용자 확인 대기)

### 10-1. 왜 바꾸나

- 카카오 로컬 API 결과는 별도로 저장해 쓰는 것이 허용되지 않고, 실시간 호출만 가능하다. (사용자가 약관에서 확인)
- 구글은 place ID 외에는 저장이 금지이고, 지도에 표시할 때는 구글 지도 위에 보여줘야 한다. (사용자가 약관에서 확인)
- 그래서 가게 목록·영업시간을 미리 모아 저장하는 현재 구조(`places.json`, `scope.json`)는 두 정책에 맞지 않는다. 두 파일은 공개 저장소에서 뺐다.
- 구현 전에 두 서비스의 약관 원문 해당 조항을 다시 확인하고, 조항 위치와 확인 날짜를 `docs/devlog.md`에 적는다.

### 10-2. 동작

1. 사용자가 **"내 근처 지금 영업 중"** 버튼을 누른다.
2. 브라우저가 위치를 받는다(사용자 허용 시). 거부하면 강남역 좌표를 기본값으로 쓰고 그렇다고 표시한다.
3. 서버(Flask)가 구글 Places API (New) **Text Search**를 호출한다. 음식점과 카페를 각각 한 번씩 물어서 지금 영업 중인 곳을 가까운 순으로 받는다.
4. 결과를 **구글 지도 위에** 마커와 목록으로 보여준다. 구글 출처 표시(속성 문구·로고)를 함께 둔다.
5. 각 결과에는 **카카오맵 검색 링크**를 단다. API 호출 없이 URL만 만든다(`https://map.kakao.com/link/search/<가게명>`). 사용자가 카카오맵에서 영업시간을 직접 비교한다.
6. **결과는 저장하지 않는다.** 서버 DB·파일·로그에 가게 정보를 남기지 않고, 브라우저 화면에서만 쓰고 버린다. (place ID는 저장 가능하지만 지금은 쓰지 않는다.)

화면에는 "구글 기준, 실제와 다를 수 있음"을 함께 표시한다. (3-5의 방침을 이어받는다)

### 10-4. 예상 호출 수와 비용

가정: 버튼 1회 = 음식점 1회 + 카페 1회 = Text Search **2호출**(결과 각 20개까지). 다음 페이지를 받으면 호출이 늘어난다(최대 3페이지 → 6호출).

| 하루/월 사용 | 월 호출 수 (2호출/회) | 비용 (무료 한도 안 여부) |
|---|---|---|
| 하루 5회 (개인 사용) | 약 300 | 무료 |
| 하루 50회 | 약 3,000 | Pro 필드만이면 무료. 영업시간 필드(Enterprise)를 쓰면 월 1,000건을 넘어 약 $70 (2,000 × $0.035) |
| 하루 200회 | 약 12,000 | Pro 기준 약 $0.032 × 7,000 ≈ $224 |

- 가격과 월 무료 한도는 이 문서의 3-3에 적은 값(2026-10-31 기준)을 쓴 추정이다. Text Search Pro는 월 5,000건 무료, 이후 1,000건당 $32. 영업시간 필드를 요청하면 Enterprise 등급이 되어 월 1,000건 무료, 이후 1,000건당 약 $35로 본다. **구현 전에 공식 가격 페이지에서 다시 확인한다.**
- 지도 로드(Maps JavaScript API) 비용은 위 표에 포함하지 않았다. 확인 후 더한다.
- 같은 버튼을 반복해서 누르면 호출이 늘어난다. 안전장치:
  - 버튼 연속 클릭 쿨다운(예: 10초)과 한 접속당 하루 호출 상한.
  - 서버 전체의 하루 호출 상한. 상한에 닿으면 "오늘은 조회 한도에 도달했습니다"를 보여 준다.
  - Google Cloud 콘솔의 일일 쿼터와 예산 알림($1).
  - 저장·캐시를 하지 않으므로 비용 절감용 캐시는 쓰지 않는다. 브라우저 화면에 이미 받은 결과를 다시 쓰는 것은 괜찮은지 약관으로 확인한다.

### 10-9. git 이력에서 두 파일 지우기 (내일 실행. 오늘은 실행하지 않는다)

목표: **커밋 기록(메시지·작성자·날짜·순서)은 그대로 두고**, 이력 전체에서 `data/places.json`과 `data/scope.json`만 지운다. 커밋 해시는 모두 바뀐다. 아래 명령은 PowerShell 기준이고, 경로는 예시다.

**주의**
- 되돌릴 수 없는 작업(강제 푸시)이 들어 있다. 반드시 1번 백업이 끝나고 검증된 다음에 시작한다.
- 이력이 바뀌므로 다른 PC·다른 작업 폴더에 같은 저장소가 있으면 모두 버리고 새로 받아야 한다. 있는지 먼저 확인한다.
- `.env`는 깃에 없으므로 이력 정리와 상관없다. 그래도 정리 전에 한 번 복사해 둔다.

**1단계: 준비와 백업**
1. 작업 중인 변경을 모두 커밋·푸시하고 `git status`가 깨끗한지 확인한다.
2. `.env`를 저장소 밖에 복사해 둔다.
3. 원격 저장소 전체를 백업한다.
   ```
   git clone --mirror https://github.com/jason-kkiimm/gangnam-latenight-map.git C:\dev-backup\gangnam-latenight-map.git
   git -C C:\dev-backup\gangnam-latenight-map.git bundle create C:\dev-backup\gangnam-latenight-map.bundle --all
   git bundle verify C:\dev-backup\gangnam-latenight-map.bundle
   ```
4. 기준값을 적어 둔다(나중에 비교용).
   ```
   git -C C:\dev-backup\gangnam-latenight-map.git rev-list --count --all     # 커밋 수
   git -C C:\dev-backup\gangnam-latenight-map.git rev-parse "main^{tree}"     # 최신 트리 해시
   git -C C:\dev-backup\gangnam-latenight-map.git branch -a ; git -C C:\dev-backup\gangnam-latenight-map.git tag   # 브랜치·태그
   ```
5. 이 백업에는 지우려는 두 파일이 들어 있다. 정리가 끝나고 문제없음을 확인한 뒤 백업을 삭제한다(그동안은 비공개 위치에만 둔다).

**2단계: 새로 받은 사본에서 이력 다시 쓰기**
1. 도구를 설치한다. `pip install git-filter-repo`, 그다음 `git filter-repo --version`으로 확인.
2. 작업 중인 폴더가 아니라 **새 폴더에 새로 받는다**(filter-repo는 새 clone에서만 동작한다).
   ```
   git clone https://github.com/jason-kkiimm/gangnam-latenight-map.git C:\dev\gangnam-rewrite
   cd C:\dev\gangnam-rewrite
   ```
3. 두 파일만 이력에서 뺀다. 두 파일만 바꾼 커밋도 **지우지 않고 남기도록** `--prune-empty never`를 붙인다.
   ```
   git filter-repo --invert-paths --path data/places.json --path data/scope.json --prune-empty never
   ```

**3단계: 푸시 전 검증 (모두 통과해야 다음으로)**
- `git log --all --oneline -- data/places.json data/scope.json` → 출력이 비어 있어야 한다.
- `git rev-list --count --all` → 1단계 4번의 커밋 수와 같아야 한다(커밋이 사라지지 않았다는 뜻).
- `git rev-parse "main^{tree}"` → 1단계 4번의 트리 해시와 같아야 한다. 최신 상태에서는 두 파일이 이미 없으므로 같아야 하고, 다르면 다른 것이 바뀐 것이니 중단한다.
- `git log --format="%h %an %ad %s" | more` → 메시지·작성자·날짜가 이전과 같은지 눈으로 확인.
- 이전 해시와 새 해시는 `.git/filter-repo/commit-map`에서 대응표를 볼 수 있다.

**4단계: 원격에 반영**
1. filter-repo는 원격(`origin`)을 지우므로 다시 연결한다.
   ```
   git remote add origin https://github.com/jason-kkiimm/gangnam-latenight-map.git
   ```
2. 강제 푸시한다. 더 안전한 `--force-with-lease`를 쓴다. 브랜치·태그가 더 있으면 같이 올린다.
   ```
   git push --force-with-lease origin main
   git push --force --tags origin   # 태그가 있을 때만
   ```
3. GitHub 쪽 확인: 저장소 페이지에서 이전 커밋 목록을 열어 두 파일이 없는지 본다. 이전 해시 주소는 한동안 열릴 수 있다. 완전히 없애려면 GitHub 지원에 캐시된 보기·PR 참조 정리를 요청해야 할 수 있다. 열린 PR이 있으면 같이 정리한다.

**5단계: 로컬 정리**
1. 기존 작업 폴더(`C:\dev\gangnam-latenight-map`)는 이전 이력을 가지고 있으므로 쓰지 않는다. 이름을 바꿔 두거나 지우고, `C:\dev\gangnam-rewrite`를 기존 이름으로 바꾸거나 새로 clone한다.
2. 복사해 둔 `.env`를 새 폴더에 넣는다. `.venv`는 새로 만든다.
3. 다른 PC·폴더의 이전 clone은 모두 지우고 새로 받는다.

**6단계: 문서 정리**
1. `docs/devlog.md`에 이력 정리 결과를 새 항목으로 적는다. 정리 날짜, 커밋 수 비교, 트리 해시 비교 결과, 해시가 바뀐 사실.
2. `docs/devlog.md` #11이 적은 이전 커밋 해시(`0461222`, `958b154`, `6850431`, `2639a37`, `2476217` 등)는 새 해시로 바꾸거나 "정리 전 해시"라고 표시한다.
3. 백업(`C:\dev-backup`)은 문제없음을 확인한 뒤 삭제한다.

**문제가 생기면 되돌리기**
- 1단계 백업에서 복구한다: `git -C C:\dev-backup\gangnam-latenight-map.git push --force --mirror https://github.com/jason-kkiimm/gangnam-latenight-map.git`. 번들(`.bundle`)에서도 복원할 수 있다.
- 3단계 검증에서 하나라도 어긋나면 4단계(강제 푸시)로 가지 않는다.
