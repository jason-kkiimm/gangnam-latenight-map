# 데이터 보강 계획 (24시간 여부 · 반려동물 여부)

작성일: 2026-10-31

## 1. 배경과 목표

- 프로젝트의 출발점은 **밤늦게 공부할 수 있는 곳 찾기**이고, 그래서 카페가 중요하다.
- 현재 `data/places.json`에는 강남역 반경 1km의 음식점·카페 **2,513개**가 있다. (카카오 로컬 API로 수집)
- 각 항목의 `is_24h`(24시간 여부)와 `pet_friendly`(반려동물 여부)는 아직 모두 `"확인 필요"`다.
- 이 문서는 두 값을 채우는 계획이다.
  - 24시간 여부: **Google Places API**
  - 반려동물 여부: **네이버 검색 API + AI 판별**
  - 이름에 "24시"가 들어간 가게 거르기: **보조 수단**으로만 사용

## 2. 조회 범위: 900개

카카오 API는 영업시간을 주지 않으므로, 2,513개 전체가 아니라 후보 약 900개만 구글에 조회한다.

| 구분 | 기준 | 개수 |
|---|---|---|
| 심야 업종 | 카테고리에 국밥·해장·설렁탕·순대·곰탕·감자탕·햄버거·패스트푸드·분식·김밥·치킨 중 하나가 포함 | 293 |
| 술집 | 카테고리에 "술집" 포함 (위와 겹치는 곳 제외) | 273 |
| 카페 | 강남역에서 가까운 순으로 334개 (가장 먼 곳이 약 694m) | 334 |
| **합계** | | **900** |

- 카페를 가까운 순으로 자르는 이유: 공부할 곳을 찾는 용도라 접근성이 중요하고, 영업시간 조회 무료 한도(월 1,000건)를 넘지 않게 맞추기 위해서다.
- 이름에 "24시" 또는 "24h"가 들어간 가게는 현재 1개뿐이다. 범위에 항상 포함하고, 구글 결과와 교차 확인하는 보조 용도로만 쓴다.
- 나머지 약 1,600개(한식·일식·양식·중식·나머지 카페 등)는 `"확인 필요"`로 남긴다. 한도가 새로 채워지는 다음 달부터 범위를 넓힐 수 있다.

## 3. 24시간 여부: Google Places API (New)

### 3-1. 호출 순서

1. **Text Search (Pro 등급)**: 가게 이름과 좌표(`locationBias`)로 검색해 `place_id`를 찾는다.
   - 응답 필드는 `id, displayName, location, businessStatus`만 요청한다. (모두 Pro 등급 이하)
   - 이름과 좌표가 카카오 데이터와 충분히 가까울 때만 같은 가게로 인정한다.
   - 폐업(`businessStatus`가 영업 중이 아님)이면 영업시간을 조회하지 않는다.
2. **Place Details (Enterprise 등급)**: `regularOpeningHours`만 요청한다.

### 3-2. 비용 (2026-10-31 공식 문서 기준)

| 호출 | 등급 | 월 무료 한도 | 한도 초과 시 1,000건당 |
|---|---|---|---|
| Text Search (Pro 필드) | Pro | 5,000 | $32 |
| Place Details (`regularOpeningHours`) | Enterprise | 1,000 | $20 |

- 900개 기준: 찾기 900건(Pro, 무료 한도 5,000 이내) + 영업시간 최대 900건(Enterprise, 무료 한도 1,000 이내) → **$0**
- 참고로 2,513개 전체를 조회하면 영업시간 조회가 (2,513−1,000)건×$20/1,000 ≈ **$30**이다.
- Text Search로 영업시간까지 한 번에 받으면 Enterprise 등급이라 $35/1,000이므로 더 비싸다. 두 단계로 나누는 쪽이 싸다.
- 가격과 무료 한도는 바뀔 수 있으니 키를 받은 뒤 Google Cloud 콘솔의 가격 페이지에서 한 번 더 확인한다.

### 3-3. 안전장치

- Google Cloud 콘솔에서 Places API의 **일일 요청 한도(쿼터)** 를 걸어 무료 한도를 넘지 않게 한다. (Place Details는 하루 약 300건 이하로 시작)
- 예산 알림을 $1로 설정한다.
- 스크립트는 한 번 조회한 결과를 파일에 저장해 두고, 다시 실행해도 이미 조회한 가게는 건너뛴다. (중복 과금 방지)
- 처음에는 20개만 시험 실행해서 결과와 청구 내역을 확인한 뒤 전체를 돌린다.

### 3-4. 24시간 판별 방식

응답의 `regularOpeningHours.periods`를 기준으로 한다.

- **24시간**: 7일 모두 0시 0분에 열고, 닫는 시각이 없거나 하루 종일 이어짐 → `is_24h = "예"`
- **24시간 아님**: 영업시간이 있고 위 조건에 해당하지 않음 → `is_24h = "아니오"`
- **영업시간 정보 없음 / 가게 매칭 실패**: `is_24h = "확인 필요"` 유지
- 24시간은 아니지만 밤늦게까지 하는 곳(예: 새벽 2시 마감)을 공부할 곳으로 쓸 수 있으므로, 요일별 마감 시각도 함께 저장하는 것을 제안한다. (`closes_at` 필드, 구현 전 확정 필요)
- 이름에 "24시"가 있는데 구글이 24시간이 아니라고 하면, 값을 바꾸지 않고 확인 대상 목록에 따로 모은다.

## 4. 반려동물 여부: 네이버 검색 API + AI 판별

### 4-1. 흐름

1. 네이버 검색 API(블로그 검색, 필요하면 카페글 검색)로 `"{가게명} 강남 반려견 동반"` 등을 검색해 상위 글의 제목과 요약문(snippet)을 모은다.
2. 모은 글을 Claude에 보내 반려동물 동반 가능 여부를 판별하게 한다.
3. 응답은 구조화된 JSON으로 받는다: `{"pet_friendly": "가능" | "불가" | "확인 필요", "evidence": "근거가 된 문장"}`
4. 근거가 약하거나 글이 거의 없으면 `"확인 필요"`로 둔다. 추측으로 "가능"을 채우지 않는다.

### 4-2. 판별 대상

- 1순위: 24시간(또는 심야) 영업으로 확인된 가게. 구글 조회 결과가 나온 뒤에 돌리면 호출 수가 훨씬 줄어든다.
- 2순위: 필요하면 900개 전체로 확대한다.

### 4-3. 비용

**네이버 검색 API**: 무료이고 하루 호출 한도가 있다. (애플리케이션당 25,000회로 알고 있으나 키를 받을 때 개발자센터에서 확인한다.) 900개 × 검색 1~2회면 한도 안이다.

**AI 판별**: 가게당 입력 약 3,500토큰(글 10개 요약 + 지시문), 출력 약 100토큰으로 어림한 추정이다. 실제 토큰 수는 `count_tokens`로 샘플 측정해서 다시 계산한다. 가격은 Anthropic 공식 가격(100만 토큰당) 기준이다.

| 모델 | 입력/출력 가격 | 900개 | 2,513개 |
|---|---|---|---|
| Claude Haiku 5.5 (`claude-haiku-5-5`) | $0.10 / $0.50 | 약 $0.4 | 약 $1 |
| Claude Sonnet 5.5 (`claude-sonnet-5-5`) | $2 / $10 | 약 $7 | 약 $20 |
| Claude Opus 5.5 (`claude-opus-5-5`) | $4 / $20 | 약 $14 | 약 $40 |

- 이 모델들은 항상 생각(thinking)을 하므로 출력 토큰이 위 추정보다 늘 수 있다. 판별에는 `effort`를 낮게 둔다.
- Message Batches API를 쓰면 가격이 50% 할인되고, 실시간 응답이 필요 없는 일괄 작업이라 잘 맞는다.
- Anthropic API 키가 따로 필요하다. (Claude Code 구독과는 별개로 과금)
- **모델 선택은 보류**: 먼저 Haiku 5.5로 샘플 50개를 돌리고, 결과가 미덥지 않으면 Sonnet 5.5로 올려 비교한 뒤 정한다.

### 4-4. 한계

- 블로그 글은 오래됐거나 광고일 수 있다. 판별 결과에 `evidence`(근거)와 글 링크를 저장해서 나중에 사람이 검증할 수 있게 한다.
- 지도 말풍선에는 "AI 추정"임을 표시하는 것을 고려한다.

## 5. 저장 데이터 형식 (제안)

`data/places.json`의 각 항목에 아래 값을 채운다. 기존 필드는 그대로 둔다.

| 필드 | 값 |
|---|---|
| `is_24h` | `"예"` / `"아니오"` / `"확인 필요"` |
| `closes_at` | 요일별 마감 시각 (제안, 확정 전) |
| `pet_friendly` | `"가능"` / `"불가"` / `"확인 필요"` |
| `pet_evidence` | 판별 근거 문장과 출처 링크 |
| `google_place_id` | 구글 매칭 결과 (재조회 방지용) |

API 원본 응답은 `data/raw/`에 저장하되 `.gitignore`에 넣어 깃에 올리지 않는다.

## 6. 진행 순서

1. [완료] 카카오 지도 연결, 강남역 반경 1km 가게 2,513개 수집
2. [대기] Google Cloud 키 발급 + 쿼터·예산 알림 설정
3. [대기] 조회 범위 900개 목록 생성 스크립트 (`scripts/select_scope.py`)
4. [대기] 구글 조회 스크립트: 20개 시험 → 900개 전체 → `is_24h` 반영
5. [대기] 네이버 개발자센터 키 발급
6. [대기] 네이버 검색 + AI 판별 스크립트: 샘플 50개로 모델 비교 → 확정 후 일괄 실행
7. [대기] 지도 화면에 24시간·반려동물 필터 추가

## 7. 열려 있는 결정

- 24시간이 아니어도 밤늦게(예: 새벽 2시) 닫는 곳을 `closes_at`으로 보여줄지
- 반려동물 판별 모델 (Haiku 5.5로 시작 후 비교)
- 반려동물 판별 대상을 24시간 가게로 한정할지, 900개 전체로 할지
- 나머지 약 1,600개를 다음 달부터 순차적으로 조회할지

## 8. 키 관리

- 구글·네이버·Anthropic 키는 모두 `.env`에만 저장한다. (`.env`는 `.gitignore`에 등록되어 있어 깃에 올라가지 않는다.)
- 키를 코드나 문서에 직접 적지 않는다.
